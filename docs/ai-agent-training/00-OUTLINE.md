# Building Apps with AI Agents: Skills, Templates, NestJS and MCP

**Audience:** developers who want to build production services _with_ AI coding agents,
and keep them consistent, tested and safe.

**How it works:** you do not type the service, your AI coding agent does. You start from a
small base, `boilerplate/nest-ai-starter/` (NestJS 12), that already has a **seeded SQLite
database**: 25 users, 200 notes (the TODO items) and 120 shares, so there is data to work with
from the first minute. In **two modules** your agent builds on it:

1. the **users** and **notes** resources (two MVCs over REST, notes shareable between users);
2. an **MCP server** on the same database, connected to your **Claude Desktop** app, so you
   can ask Claude about the data and have it change it.

The proctor gives each step as an **instruction**: the goal, where the requirements are, and
when it is done, never the steps. You give it to your agent, in your own words or as
written; the agent works out how (from the repo's `CLAUDE.md`, its skills and its specs) and
you watch its approach. Then you **check** the result with a lab check and `npm run verify`, and
**review** what it wrote. It runs on Node 24 and npm (chapter 00); the database is one file,
so there is no database server to install.

Repeatable work is done by tools (nest-cli, templates, a verify gate). Judgement is done by the
agent inside marked regions, guided by the skills in `.claude/skills/` and the specs in
`specs/`. Every claim in the chapters was measured on this code, and the traps we hit are part
of the material.

## The track: two modules

Every module runs the same loop:

```
proctor → instruct → agent → check → review
```

| module                       | reading            | your agent builds                                                                          | you check                                          | lab |
| ---------------------------- | ------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------- | --- |
| 1 Users and notes            | ch00 + ch01 + ch02 | sets the project up, then users and notes (with sharing) on the tables                     | lab 01 · break a rule, see red                     | 15' |
| 2 An MCP server on your data | ch03 + ch04        | a stdio MCP server that queries and changes the database; you connect it to Claude Desktop | lab 02 · Claude Desktop reads and writes your data | 15' |

Both lab times (about 15 minutes each for Claude Code to finish the module) are estimates;
nobody has run the course with an audience yet.

Each module ends at a **checkpoint**. If your agent went somewhere you cannot recover from in
the time, catch up from `checkpoints/` and carry on. The branch `modules-done` of the course
repository has both modules as an AI agent built them from these instructions.

The proctor deck is `slides/lab-companion.pptx` (and `.md`), generated by
`slides/build-lab-deck.mjs`.

## Ground rules for the material

- No credentials, tokens, internal hosts or customer data; placeholders such as `<SECRET>`.
  Every commit passes `tools/scan-sensitive.sh`.
- Incidents from the estate appear only as anonymised lessons.
- Every lab is checked by evidence, never by "it worked".
